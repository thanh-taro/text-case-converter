## Context

The portal now passes the user's language to embedded tools as `?lang=` (`en-US`, `vi-VN`) and
can switch it live (F-011, RULE-10, RULE-15). The tool must show the right language from first
display, follow live switches without losing input, keep the single source of strings
(ADR-0007) and the size budget (NFR-05), and render Vietnamese in its own typefaces. ADR-0008
(theme contract) and ADR-0007 (copy generation) stay in force; this ADR extends both.

## Decision

1. **Address.** `?lang=` is read with the theme by the inline, CSP-hashed boot script, which
   resolves the language per RULE-15 (address → `navigator.languages` → `en-US`) and sets
   `<html lang>` before first paint. The app reads the same resolution at start, so the first
   render is already in the right language (no flash: strings are rendered only by the app).
2. **Live switch.** A settings message `{ type: "taro:lang", value }` is accepted under the exact
   ADR-0008 rules (allow-listed `event.origin`, `event.source === window.parent`); unsupported
   values are ignored. The latest accepted message wins over the address. No new outbound message.
3. **Catalog.** `copy.md` holds one column per language; `scripts/gen-copy.mjs` generates one
   typed catalog with both languages and fails the build if any string is missing a language or
   the placeholders differ (F-011.AC11). The active language is a signal in MOD-Copy; `t()` reads
   it, so components re-render on a switch with their state intact. Both languages ship in the
   main bundle (a few hundred bytes compressed) — no lazy loading, no i18n library.
4. **Formatting.** Counts use `Intl.NumberFormat(activeLanguage)`. Casing stays locale-independent
   (ADR-0011); the alphabetical sort is unchanged because case labels are not translated.
5. **Fonts.** Add only the `vietnamese` subset of the already-approved Manrope (DEP-12), as an
   extra `@font-face` with its `unicode-range`. It is requested at startup in every language
   (`document.fonts.load`), as part of the initial load, so the offline worker's seed list — taken
   after `document.fonts.ready` — caches it (ADR-0010) and no font request ever follows the load or
   depends on what the user types or on a live language switch (NFR-01, INV-01). JetBrains Mono
   (DEP-13) is unchanged: results are user content, outside F-011. `latin-ext` is not needed.
6. **Document title** is set from COPY-app.title at start and on every switch.

## Alternatives considered

- **An i18n library (e.g. i18next, FormatJS)** — far more weight than 2 languages × ~35 strings need.
- **A build per language** — doubles deploys and cannot switch live (F-011.AC3).
- **Address only** — cannot follow a live portal switch; rejected by the owner.

## Consequences

- One more inbound message type; the outbound contract is unchanged (INV-01).
- The boot script's CSP hash changes (regenerated by `scripts/gen-headers.mjs`).
- ~9 KB more font download on first visit in every language (within the font budget).
- Visible case labels carry `lang="en"` inside a vi-VN page (NFR-04).
- Adding a language later = one column in copy.md + one entry in RULE-15's list.
