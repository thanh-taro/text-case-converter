# Rules & limits

These rules define observable behavior. The exact tokenization choices for acronyms and numbers
(RULE-02) are the default the tool ships with; they are validated against an adversarial corpus
during architecture and may be refined there before the specs reach `ready`.

| ID           | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RULE-01**  | **Case kinds.** The tool shows eleven results for the current input. Nine are _token-based_ (the input is tokenized by RULE-02, then the tokens are re-joined); two (`UPPERCASE`, `lowercase`) are _character-based_ (RULE-01b). Token-based joins, where each token's letters are lowercased unless stated otherwise: **camelCase** — first token lowercased, every later token's first cased letter uppercased; no separator. **PascalCase** — every token's first cased letter uppercased; no separator. **snake_case** — tokens lowercased, joined with `_`. **kebab-case** — tokens lowercased, joined with `-`. **CONSTANT_CASE** — tokens uppercased, joined with `_`. **dot.case** — tokens lowercased, joined with `.`. **path/case** — tokens lowercased, joined with `/`. **Title Case** — every token's first cased letter uppercased, rest lowercased, joined with a single space (RULE-04). **Sentence case** — the first token's first cased letter uppercased, all other letters lowercased, joined with a single space (RULE-04). |
| **RULE-01b** | **Character-based kinds.** **UPPERCASE** maps every cased character of the input to its upper form; **lowercase** maps every cased character to its lower form. Both leave all other characters — spaces, `_`, `-`, `.`, `/`, digits, punctuation, line breaks — exactly in place. These two never tokenize, so existing delimiters and structure are preserved.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **RULE-02**  | **Tokenization** (token-based kinds only), applied to each line independently (RULE-03). A _word character_ is a Unicode letter or digit; every other character is a _separator_. Scanning a line left to right, a token boundary occurs: (a) at each run of one or more separators, which are discarded; (b) before an uppercase letter that follows a lowercase letter or a digit (`fooBar` → `foo`,`Bar`; `v2Point` → `v2`,`Point`); (c) before the last uppercase letter of a run of two or more uppercase letters when that last letter is followed by a lowercase letter (`HTTPResponse` → `HTTP`,`Response`; `parseURLToString` → `parse`,`URL`,`To`,`String`). Digits stay attached to the token they appear in (`utf8` → `utf8`; `userID2` → `user`,`ID2`); there is no split between a letter and a digit. Empty tokens are dropped.                                                                                                                                                                                                     |
| **RULE-03**  | **Per-line conversion.** Input is split into lines at line breaks. Each line is converted independently; a result is the per-line conversions joined back with a line feed, preserving the number of lines. A blank line, or a line with no word characters, converts to an empty line (for token-based kinds).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **RULE-04**  | **Title & Sentence case.** First-letter-of-each-token (Title) or first-letter-of-the-line (Sentence) capitalization only; there is no stop-word list, so short words like _the_, _of_, _a_ are capitalized in Title Case. This is a documented, intentional simplification.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **RULE-05**  | **Casing & Unicode.** Upper/lower mapping is locale-independent (so the Turkish dotless-i and similar locale traps do not apply). Characters with no case — digits, punctuation, CJK, emoji, most non-Latin scripts — pass through unchanged and are preserved within their token; combining marks are preserved. A token made only of non-cased characters appears unchanged in every token-based result.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **RULE-06**  | **Acronym normalization (known limitation).** In token-based kinds, after a token's first letter is cased, the rest of its letters are lowercased, so `ID` becomes `Id` in PascalCase/camelCase (`getUserID` → `getUserId`). Preserving acronyms as all-caps is out of scope for M-1 (a candidate toggle for a later milestone). `CONSTANT_CASE`, `UPPERCASE`, `snake_case`, etc. are unaffected because they case the whole token uniformly.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **RULE-07**  | **Copy.** Activating a result copies that result's full text (all lines) to the clipboard and shows a brief confirmation. Copying happens only on an explicit user action; it records the case as most-recently-used in per-device preferences (RULE-13/RULE-14, not user content), sends nothing off the device, and stores no user text (PRN-01, INV-01).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **RULE-08**  | **Responsiveness cap.** Results are recomputed whenever the input changes. _Settling_ means the first idle interval after the last change; the settle delay is about 150 ms. Below the cap of 100,000 characters, results recompute once the input settles, so typing and pasting stay responsive (PRN-06, NFR-02). Past the cap, the tool shows a notice once per session (COPY-notice.large), dismissible, and recomputes only after the input stops changing; it never blocks the interface.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **RULE-09**  | **Empty input.** When the input has no characters, every result is empty, no confirmation is shown, and copy is unavailable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **RULE-10**  | **Host settings contract.** The host passes the initial theme (`light` or `dark`) in the tool's address when opening it; later changes arrive as settings messages. The tool signals the host once it is ready; that ready signal is the only message the tool ever sends, and it never contains user text. The list of allowed host origins is fixed when the tool is deployed and decides both who may embed the tool and whose messages are accepted. If the list is empty, the tool runs standalone only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **RULE-11** | **Strip symbols** (M-2 preference, default off; RULE-14). When on, results are built from the RULE-02 tokens with each token reduced to ASCII letters and digits only: accented Latin letters are first folded to their ASCII base (the RULE-12 fold, so `é`→`e`, `đ`→`d`), then every remaining character that is not an ASCII letter or digit — punctuation, symbols, whitespace, and letters of non-Latin scripts (CJK, Greek, Cyrillic, emoji) — is dropped. Token-based kinds render these cleaned tokens; the character-based kinds (RULE-01b), which otherwise fold the raw input, instead render the cleaned tokens joined by a single space. A token that becomes empty is dropped. Example: `café, v2!` → tokens `café`,`v2` → `cafe`,`v2` → snake_case `cafe_v2`, UPPERCASE `CAFE V2`; `Nguyễn 日本` → `nguyen` (the CJK token drops to empty). |
| **RULE-12** | **Remove accents** (M-2 preference, default off; RULE-14). When on, accented Latin letters are folded to their ASCII base before casing, using Unicode canonical decomposition (NFD) with combining marks removed, plus an explicit map for Latin letters that do not decompose: `đ`→`d`, `Đ`→`D`, `ø`→`o`, `Ø`→`O`, `ß`→`ss`, `æ`→`ae`, `Æ`→`AE`, `œ`→`oe`, `Œ`→`OE`, `ł`→`l`, `Ł`→`L` (Vietnamese is covered by NFD plus the `đ` map). Symbols, digits, whitespace and non-Latin scripts are left unchanged (RULE-05 still governs them) — unlike RULE-11, this keeps them. Example: `Nguyễn Đặng` → `Nguyen Dang`; `café, v2!` → snake_case `cafe_v2`, UPPERCASE `CAFE, V2!` (comma and space kept). |
| **RULE-13** | **Result order & recent use** (M-2 preferences; RULE-14). The grid is ordered by one _sort mode_: `default` (the fixed RULE-01 order), `recent` (cases by how recently they were copied, most-recent first; cases never copied follow in RULE-01 order), or `alphabetical` (by case label, case-insensitive). Independently, any case can be _pinned_; pinned cases appear first, keeping the active sort among themselves and among the rest. Copying a result (RULE-07) marks its case as the most-recently-used; that one case shows a **last-used badge** (COPY-badge.last_used) on its row in every sort mode and across sessions, until another case is copied. Order, pinning and the badge change only row position and marking — never a result's text (INV-02). |
| **RULE-14** | **Preferences.** The strip-symbols (RULE-11) and remove-accents (RULE-12) toggles, and the sort mode, pins and recent-use order (RULE-13), are per-device _preferences_ (ENT-Preferences), not user content. They are remembered in per-device storage and restored on next open; no input text is ever stored (PRN-01, INV-01), and preferences are never sent anywhere (INV-01). If per-device storage is unavailable, the tool runs with default preferences for the session. |
